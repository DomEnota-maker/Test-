# QA / Acceptance — VL80С `pantograph-no-rise` Reference Pack

## 1. Контентная полнота

Эталонный pack содержит **19 Knowledge Entry** и должен оставаться достаточно насыщенным, чтобы UI проверялся на реальном объёме, а не на заглушках.

Покрыты классы:

- `NORMATIVE` — 2;
- `TECHNICAL_REFERENCE` — 4;
- `OPERATIONAL_EXPERIENCE` — 3;
- `MAINTENANCE_PRACTICE` — 2;
- `HISTORICAL` — 2;
- `ARCHIVE` — 1;
- `CASE_STUDY` — 2;
- `FIELD_PRACTICE` — 1 restricted;
- `UNSAFE_METHOD` — 1 restricted/redacted;
- `UNVERIFIED` — 1.

`MANUFACTURER` намеренно не заполнен: первичный заводской источник, однозначно относящийся к нужному исполнению, в этой исследовательской сессии не получен. Качественная система должна уметь показывать этот пробел, а не заполнять его догадкой.

## 2. Проверка целевых метаданных

Каждая запись должна пройти валидацию наличия:

- `classification`;
- `statementType`;
- `confidence`;
- `applicationStatus`;
- `knowledgeLayerDepth`;
- `visibility`;
- `applicability`;
- `sourceRefs`;
- `limitations`;
- `relations`;
- `qualityControl`.

Дополнительно restricted-записи должны иметь явный `restrictedProcedure` или эквивалентный policy marker.

## 3. Покрытие enum-значений

В наборе должны реально встречаться, а не только существовать в enum:

### Statement Type

- FACT;
- OBSERVATION;
- HYPOTHESIS;
- RECOMMENDATION;
- CASE_REPORT.

### Confidence

- VERIFIED;
- SUPPORTED;
- REPORTED;
- UNKNOWN.

### Application Status

- REFERENCE;
- EXPERIENCE;
- PRACTICE;
- ACTIONABLE;
- RESTRICTED.

## 4. Source integrity

Fail, если:

- `sourceRefs` пуст;
- ссылка указывает на несуществующий source ID;
- запись уровня C/D автоматически стала нормативной;
- библиографическая запись 2025 года используется для процедуры, полный текст которой не был доступен;
- вторичный источник по №631 стал hardcoded profile rule.

## 5. Variant / applicability QA

Обязательные кейсы:

1. Пособие Потанина/Куприна не должно трактоваться как универсальная схема всех ВЛ80С: авторы явно ограничивают базовую схему диапазоном выпусков и рассматривают модификации отдельно.
2. Серийная граница реле 248 около №631 остаётся `REPORTED` до первичного подтверждения.
3. Тип токоприёмника на конкретной машине не выводится только из слова «ВЛ80С».

## 6. Conflict QA

### `PANTO-PRESSURE-POINT-001`

Pass, если UI/модель умеют сохранить несколько значений с разными точками/условиями и показывают «требует уточнения», а не выбирают одно число.

Fail, если значения усредняются, одно молча объявляется нормой или конфликт исчезает при сериализации.

### `PANTO-FIELD-SAFETY-001`

Pass, если:

- существование полевого метода может быть `SUPPORTED`;
- его `applicationStatus` остаётся `RESTRICTED`;
- normative/safety слой не понижается из-за существования практики.

## 7. Visibility QA

### BASIC + MINIMAL

Должны быть доступны:

- ядро неисправности;
- safety-контекст;
- понятный первый вопрос;
- ход проверки;
- только необходимые технические пояснения.

Не должны быть доступны:

- архив;
- историческая детализация;
- ремонтные подробности;
- FIELD_PRACTICE / UNSAFE_METHOD.

### EXTENDED + STANDARD

Должны добавляться:

- эксплуатационные наблюдения;
- технические связи;
- case studies;
- расширенные направления поиска.

### EXTENDED + DETAILED

Должны быть доступны:

- история;
- ремонтная практика;
- source/QC metadata;
- конфликтующие сведения;
- вариантные заметки.

### EXTENDED + restricted gate OFF

**Критический тест:** обычный Extended продолжает работать, но `FIELD_PRACTICE`/`UNSAFE_METHOD` с `extendedEmergencyRequired=true` скрыты.

### EXTENDED + restricted gate ON

Restricted-записи могут быть показаны как отдельный явно маркированный слой. Они не становятся `ACTIONABLE` автоматически.

## 8. Dynamic Card QA

### Кейс «воздух/утечка слышны, подъёма нет»

Ожидаемое поведение:

- поднять релевантность пневматико-механической ветви;
- показать соответствующий operational/case слой при разрешённой глубине;
- оставить альтернативные ветви доступными;
- не писать «неисправен шланг» как установленный факт.

### Кейс «один токоприёмник против всех»

Ожидаемое поведение:

- изменить приоритет локальная/общая ветвь;
- не завершать граф одним наблюдением.

### `Не знаю`

- не равно `Нет`;
- не создаёт отрицательное evidence;
- не обнуляет альтернативы;
- при наличии безопасного способа наблюдения может открыть пояснение «как уточнить».

## 9. Single Source of Truth QA

Fail, если интеграция создаёт новые независимые текстовые сущности «токоприёмник 245/248» только для карточки.

Pass, если Knowledge Entry связывается с canonical component IDs существующего Atlas/technical слоя.

## 10. Restricted content QA

В reference pack нет пошагового payload опасного обхода.

Fail, если Work при интеграции автоматически подтягивает из внешней статьи номера перемычек/принудительные действия и делает их обычным текстом карточки.

## 11. Пользовательский UI

В интерфейс не должны попадать:

- `vl80s-panto-*`;
- `VL80S-PANTO-S*`;
- `PANTO-*` conflict IDs;
- `VL-EQ-*`;
- внутренние enum/quality/status keys.

Пользователь видит локализованные названия и понятный статус; служебные ID остаются только в данных/отладке.

## 12. Финальный статус приёмки

Reference pack можно считать интегрированным корректно только если одновременно:

- JSON/asset validation зелёный;
- 19/19 записей не потеряли metadata;
- все `sourceRefs` разрешаются;
- все relations разрешаются либо явно помечены как pending canonical entity;
- restricted gate независим от Extended knowledge mode;
- три conflict/uncertainty case сохраняются;
- Base не перегружен;
- Extended действительно заметно богаче Base;
- Detailed выдерживает полный объём без визуального развала;
- диагностика не начинает утверждать причины по одному признаку;
- существующий `pantograph-no-rise` graph не регрессировал.
