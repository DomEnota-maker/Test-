# VL80С — «Токоприёмник не поднимается»: эталонный Reference Knowledge Pack

## Назначение

Этот пакет подготовлен как **эталон наполнения** для сценария `pantograph-no-rise` перед интеграцией в Diagnostic Framework v2.

Он специально не изменяет runtime-код и не подменяет текущую работу ветки `feature/diagnostic-framework-v2`. Work должен интегрировать пакет отдельно после стабилизации схемы данных и UI.

Базовая точка ветки: `2a61a85aa3367768e5de4d35833d8c091f48c873` (`feature/diagnostic-framework-v2`).

## Почему это отдельный пакет

Тест новой карточки нельзя проводить на четырёх коротких демонстрационных абзацах. Реальный UI должен выдержать одновременно:

- штатную техническую информацию;
- нормативные ограничения;
- эксплуатационные наблюдения;
- ремонтную практику;
- исторические и архивные материалы;
- конкретные случаи;
- непроверенные/вариантные сведения;
- конфликтующие данные;
- ограниченные полевые/нештатные методы.

Поэтому пакет создан не как «ещё одна инструкция», а как набор **утверждений с происхождением, применимостью и статусом**.

## Ключевые правила

1. **Не хранить «истину» без происхождения.** Каждая содержательная запись имеет `sourceRefs`.
2. **Достоверность не равна допустимости.** Подтверждённый факт существования полевого метода не превращает метод в штатное действие.
3. **Наблюдение не равно рекомендации.** `OBSERVATION` и `CASE_REPORT` нельзя автоматически превращать в `ACTIONABLE`.
4. **Историческое не удаляется из-за возраста.** Оно получает явную применимость и статус.
5. **Противоречия не скрываются.** Для них предусмотрены `conflictGroupIds` и `interpretationNotes`.
6. **Серийные/вариантные границы fail-closed.** Если источник вторичный или исполнение не подтверждено, запись остаётся `REPORTED/UNKNOWN` и требует profile gate.
7. **Нештатные обходы не публикуются как процедура.** Пакет фиксирует факт существования и контекст таких методов, но пошаговые перемычки/принудительное включение защит в unrestricted-данные не переносятся.
8. **Base / Extended / Restricted — разные оси.** Расширенный режим знаний может быть включён при выключенных расширенных аварийных приёмах. Restricted-записи требуют отдельного gate.

## Состав

- `reference_pack.json` — эталонные записи знаний с целевыми метаданными.
- `SOURCE_MATRIX.md` — матрица источников, их уровня и ограничений.
- `INTEGRATION_NOTES.md` — карта интеграции с текущей реализацией Work.
- `QA_ACCEPTANCE.md` — критерии приёмки после интеграции.

## Целевая модель записи

Каждая запись по возможности содержит:

- `classification`;
- `statementType`;
- `confidence`;
- `applicationStatus`;
- `knowledgeLayerDepth`;
- `visibility`;
- `applicability`;
- `summary` / `details`;
- `limitations`;
- `sourceRefs`;
- `relations`;
- `qualityControl`.

## Важная граница достоверности

Пакет является **исследовательской эталонной выборкой**, а не автоматически утверждённой эксплуатационной инструкцией. Перед production-переносом записи уровня `ACTIONABLE`, нормы, серийные границы и действительность нормативных документов должны пройти отдельную человеческую/профильную проверку.

## Что здесь намеренно НЕ делается

- не переписывается весь ВЛ80С;
- не меняется текущий parser Framework v2;
- не выполняется массовая миграция сценариев;
- не добавляются пошаговые опасные обходы защит;
- не объявляются первичными те источники, которые доступны только как репринт/зеркало/сообщество.
